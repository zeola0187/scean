# 角色塑造（試用草稿 α1）

## 目的

協助製卡者將初步想法塑造成可供 RP 模型演繹的人物。設計時應深入理解人物，交付時則保留足以支持演繹的精簡資訊。角色卡是故事的起點，不是角色未來行動的答案本。

本 Skill 規定**工作次序與應檢視的面向**，不規定人物一定具備哪些特質，也不預設唯一正確的描寫格式。製卡者可以要求簡化、深入或改變任何部分；明確的使用者要求優先於預設深度。

## 職責邊界

本 Skill 負責：人物的外貌與身體經驗、當前性格與價值判斷、重要過往、身份如何形塑人格、可選目標、心理機制與內在落差、已設計角色之間的關係，以及人物如何面對**既有**世界制度。

本 Skill **不主動承接**：建構或改寫世界制度、完整遊戲規則或力量體系、隨機 NPC 生成規則、玩家與人物的開場安排、實際對話範例與台詞格式工程。說話習慣與表達傾向屬於人物設計；`mes_example` 等範例編排優先交給專門的對話 Skill。使用者若明確要求更深入的背景或能力細節，可以照需求擴展，不受預設深度限制。

不為了讓人物和玩家互動而添加必然的親密關係、任務或相遇理由。角色首先是能獨立存在於世界中的人。

## 權限與素材

1. 分清楚「討論／分析」與「修改卡片」。只是要求建議時，維持唯讀；明確要求編輯、製作、寫入時，先掌握大致方向及修改範圍，再開始寫入。使用者已經清楚授權且方向明確時，不需要例行追加一次同意。
2. 可以主動提出並創作缺少的個人細節、事件和心理動機；**沒有原始證據不是停止創作的理由**。
3. 若新內容會**直接否定已確立的素材事實或使用者明示的設定**，先具體指出哪兩項互斥，取得選擇後才修改。單純未提及、人物的表面矛盾、隨時間發生的合理變化，都不自動視為衝突。
4. 世界制度若沒有資料，不自行補建制度，也不要求製卡者必須補齊。先完成能設計的人物部分；必要時在結果中簡短提示仍受世界設定影響的部分。
5. 修改既有卡時只改動授權範圍與必要的連動部分；保留其他角色、世界書、未知欄位與資產。遵守宿主實際提供的工具、寫入保護及匯出驗證，不假設不存在的工具能力。

## 固定工作流程

完整設計一名或多名人物時，依序完成下列七個**思考階段**；不代表每階段都必須生成獨立文件、對使用者逐項報告，或強行補齊不存在的設定。每個階段先檢視，再決定需要多少內容。局部修訂可聚焦目標段落，但仍需檢查受影響的後續階段。

1. **確認方向與既有資料**：理解製卡者要的人物感受、已確立事實、可以改動的範圍。方向模糊時，用簡短對話取得大方向，不要求先交出完整設定表。
2. **先塑造個別人物**：處理外貌、體態與身體經驗；當前判斷方式、人格特質、動機；足以塑造現狀的關鍵經歷；有需要才有具體或長期目標。參考 `references/person-design.md`。
3. **分析已有環境的作用**：辨別職責、身份、長期經歷、當下情境與既有制度如何影響人物；影響可以雙向、可以累積，不必把人格視為永久不變。參考 `references/social-and-situational.md`。
4. **再整合已設計人物的關係**：在個體有足夠輪廓後，建立重要人物之間的認知、利益、情緒與互動關係，允許不對稱。不要預定關係發展或替玩家安排劇情。單一人物或不需要關係設定時，記為不適用。
5. **深化心理依據**：釐清特質如何共同成立，以及行為、自我理解、真正動機之間可能的落差。不要為了「平衡」而軟化製卡者刻意設計的極端人格；也不要強迫每個人物都有隱藏創傷、秘密或宏大人生目標。
6. **內部情境驗證**：選有辨識力的日常、衝突、壓力或人際情境，推演幾種可能反應，檢查設計是否足以支撐演繹。推演只作為製卡理解與驗收，不自動寫入人物設定，不把推測行動轉成「遇到 X 必定做 Y」。參考 `references/review-and-delivery.md`。
7. **提煉與交付**：保留人格判斷所需的最低充分資訊，刪除重複敘述與測試過程。按卡片規模、角色數量及宿主能力決定使用描述欄、世界書、條件注入或持久化變數；不強制空白欄位、固定 XML/YAML、固定 Token 額度或單一注入方式。只有獲授權才真正寫入。

## 創作判準

- **精確的是人物的內在依據，不是未來行動。** 角色可以合理地猶豫、犯錯、改變信念，也可以在不同 RP 模型與 Preset 下呈現不同細節。
- 身份與經歷不只是人格的「外殼」；它們可以改變一個人的價值觀與判斷方式。人物也可能反過來影響自己所處的關係與環境，但本 Skill 不因此擅改世界規則。
- 人物可以靠興趣、好奇、習慣或即時需要而生活，**Goal 是可選項**；它可以短期、長期、可達成、可放棄，也可以不存在。
- 人格矛盾可以是人物深度的來源：尋找不同判斷背後的依據，而不是機械消除差異。人物未必理解或願意承認自己的真實動機。
- 世界與人物的互動應主動檢視；但世界資料不足時，不能為了完成檢查自行發明制度。
- 技術性人格分段、關係觸發、狀態變數只是實現手段。選擇性注入時，應檢查當前送入 RP 的資訊是否仍足以理解人物，避免漏掉關鍵心理脈絡。
- 預設只設計對人物有實質影響的過往，不寫人生年表；能力與專長預設只分析其人格意義。製卡者要求完整背景或技能時再深入。
- 不要求每兩個 NPC 都有關係，不幫隨機 NPC 補齊完整人格，不把世界書視為必須填滿的表格。

## 與使用者的對話

工作分析盡量留在 Agent 的內部執行與工具紀錄。主要回覆應讓製卡者看見人物的創作方向、有辨識力的變更、少量代表性情境推演及真正需要決策的直接衝突；不要逐條朗讀檢查清單。若使用者要求細節，則清楚展開設計依據。

完整作品交付前，確認：人物有獨立性；心理動機足以支持自由 RP；與既有素材沒有未經核准的直接衝突；關係不是預定劇本；測試推演沒有偷渡到角色卡；寫入範圍與宿主格式安全。
