# 給 Codex 的隔離整合任務

請先閱讀本包的 `character-authoring/SKILL.md`、三份 references 與 `TRIAL-GUIDE.md`，然後在 `zeola0187/dsh-card-studio` 專案進行**只限隔離測試**的整合。此任務目標是「讓使用者能安全試用新角色塑造 Skill」，不是重構插件。

## 必要邊界

1. 不改動日常安裝的 Card Studio 1.0.0、不覆蓋現用工作區或私人角色卡，不改 DSH runtime、Host 安全邊界、已封版 tag/release，也不推送 GitHub 或建立公開倉庫。
2. 使用新的工作分支、worktree 或獨立測試資料夾／安裝位置；保留原本版本可完整回退。
3. 將本包 `character-authoring` 註冊為測試用 Skill，並使三份 references 能被宿主正確讀取；依實際 SDK／DSH 契約做最少必要的相容處理。
4. 測試環境中，停用與新 Skill 功能重疊的 `palette-personality-reconstruction`、`character-design-deepener`，避免模型同時收到互相矛盾的方法論。**私人正式版本的原始檔案、來源紀錄與註冊配置不要刪除或改動**。
5. 如果現有框架要求額外 adapter，請以最小且可逆的檔案處理，維持 Skill 的設計意圖；不要自行修改「創作自由、核准界線、七階段、世界與玩家職責、情境測試不入卡」等方法論。若非修改不可，先列明衝突點。
6. 不下載或複製 Arcamage、Echo 等舊 Skill 的內容到這份新 Skill。不要把既有私人 Git 歷史直接推入新的公開倉庫。

## 驗收範圍

- Skill 能成功被宿主發現，名稱、描述與三份 reference 路徑正確。
- 新舊人格／角色深化 Skill 不會同時觸發測試對話。
- 有讀取、分析與修改卡片的權限界線：純分析唯讀；已授權編輯可施工；遇直接素材衝突會要求決策。
- 簡單的多角色測試：先個別塑造角色，再整理角色關係；世界設定不足時不自動造制度。
- Agent 的情境推演與最終寫入分離，測試案例沒有落入卡片。
- 完成必要回歸檢查，並明確區分「程式測試通過」與「實際創作品質仍待使用者體驗」。

## 交付格式

只回報：改了哪些檔案、如何啟動隔離測試、如何恢復原狀、實際執行的測試及 PASS／FAIL、尚未驗證的地方。不要做額外介面美化、技能管理器重構、runtime 改造、複雜自動評分或正式發布。
