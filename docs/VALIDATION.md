# Validation and known limits

The 1.4.2 release carries the compact reader, the single W01 panel following the
latest valid prose, and DSH-native RP output-default inheritance. Suite, Runtime
and Studio have aligned version and source-offer metadata.

The user reported successful formal play acceptance on their existing Windows /
DSH installation and explicitly approved publication. That user acceptance is
separate from engineering checks. It does not certify every provider, all literary
outputs, every supported DSH version, WAN route or operating system.

Before stable version alignment, the accepted functional candidate passed Runtime
794/794, Native Authoring 28/28 and isolated Web/native UI 18/18 each. Studio had
312 passes and seven retained failures from missing historical SDK / app-asar /
SillyTavern fixtures; the identical failures were reproduced on its baseline.
No test was removed or converted to skip/pass. The release's detached verification
receipt records actual version-aligned and clean-public-source reruns, hashes,
anonymous downloads and official isolated homepage installation. This source
document does not certify a future modified rebuild.

Synthetic UI acceptance uses real shared UI, generated native client, Host, Core,
Store and SDK with invented cards, Runs and provider output. The outer DSH/React
mount is a shim. Desktop, tablet and 390px viewports do not constitute additional
physical-device, keyboard/touch, authenticated Desktop login or other-OS coverage.
One intermediate Web iframe wait timed out; its cause was not established and
final Web/native reruns passed. No unrelated UI fix is claimed.

Engineering verification does not add paid-model or external-embedding requests,
retry private Runs, or update an active installation. Real provider wire parameters
and future completion remain outside offline guarantees; SDK prepared defaults
must not be relabelled as observed final provider limits.

Public source excludes separately licensed SDK binaries, extracted application
trees, user cards/Runs/prompts, private reports, credentials, backups and Git history.
Obtain and verify a supported DSH app.asar as described in README.md for SDK tests.
The machine guard remains fail-closed.
