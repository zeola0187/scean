# 1.4.2 閱讀介面與 RP 輸出設定

## 閱讀與輸入

正文採用較緊湊的閱讀版面。卡片標題保留，重複的版本列與輸入區說明移除；
輸入區靠近底部，送出與取消位於右側。回合操作、章節回顧、備份與舞臺全域設定
整合至既有頂部的單一設定入口，不增加一整列工具列。

收合的書架與「此刻」以左右邊緣標籤開啟；窄螢幕採側欄覆層。
鍵盤可使用 Tab、Enter／Space 操作，Escape 返回正文；送出仍使用 Ctrl／⌘＋Enter，
IME 組字期間不送出。控制保留可見焦點與觸控目標，正文有自己的捲動範圍。

## 卡片動態面板的位置

卡片面板跟在最新有效正文後，位於輸入前。每局保留同一份 iframe，不為每輪複製整份前端。
原先開場位置固定與狀態更新是兩件事：狀態原本會更新，本版調整的是掛載與閱讀位置。

只載入舊歷史且尚未包含最新有效尾端時，暫時隱藏面板，避免把目前狀態誤認成該歷史回合狀態。
回到最新尾端後再次顯示。閱讀舊文時抵達的新回合盡量保留原閱讀位置；
若正在閱讀的回合因再生成而失效，介面會說明並轉至仍有效的內容。

取消、失敗、回退、再生成、繼續遊玩與備份匯入依照有效的 canonical head 對齊。
W01 狀態投影、ACL、Snapshot 與 sandbox／CSP 契約不變，卡片不能新增 Host Action 或腳本權限。

## RP 輸出額度

`director`、`character`（CR）、`adjudicate`、`draft`、`prose`、`prose_repair` 與 `post_stat`
省略固定的 `maxTokens`。模型選擇優先序保持原樣，輸出預設交由該次選定的 DSH provider／model 決定。
先以 SDK `prepareCall()` 準備，再使用同一個 prepared handle 派送。
保存設定生效後，下一個新請求取得新值；已準備的請求保留自己的設定快照。

舊 plugin 全域與 stage cap 不再覆寫上述七個 RP 階段。
原生背景 `summary`、`chapter_analysis`、`chapter_summary`、`chapter_rerank`
維持原有 4,096 預設與明確設定；本版沒有擴大背景模型權限或 Session／Agent 選項繼承。

SDK 未揭露輸出預設時保持省略與未知，不猜成固定 4,096，也不宣稱無上限。
SDK 準備值不等於 provider 最終 wire 值：adapter 可能依上下文或 thinking 再調整。
診斷中的最終 wire 上限保持未知，另保留安全的 SDK finish kind 與實際用量。

較大的額度可能增加等待與用量；180 秒階段逾時、回應大小上限與截斷拒絕仍存在。
不完整的 PostStat 不會提交 State；舊失敗回合不會因更新自動重試。

## 升級與驗收界線

先等待生成與保存完成，停用整個 suite，再備份 Run、Studio 工作區、舊套件與非秘密安裝設定。
使用 DSH 官方卸載及安裝流程；執行中的檔案不應直接覆蓋。保留相應版本的程式與資料備份，
回退資料前先確認沒有較新的工作。既有具名備份仍使用 v4，舊版相容限制見[姓名與備份](PLAYER-NAME.zh-TW.md)。

使用者已在既有 Windows／DSH 環境完成本次功能候選的正式遊玩驗收並批准公開發布。
工程流程另外執行離線模型、隔離 Web／原生掛載及安裝驗證；正式發布的版本、來源標示同步為 1.4.2。
這些證據不代表其他作業系統、所有 DSH 版本、所有模型或所有網路環境已驗收。
本次工程驗證不新增付費模型或外部 embedding 呼叫；實際結果及保留的基線失敗列於 Release 附件。
