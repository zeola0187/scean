## 2. Desktop 隔離方式

DSH Desktop 是 Electron 程式。它的 Host 是同一個執行檔以 Node 模式啟動的子行程，插件安裝則走自己的插件管理與內建 pnpm。我採用的隔離方式：

| 層面 | 做法 |
|---|---|
| 程式本體 | 複製 `E:\DSH` 到預覽資料夾並移除 `app-update.yml`，打包版的自動更新因此停用，不可能升級或覆寫正式安裝。 |
| DSH 資料 | 環境變數 `DSH_HOME` 指向預覽資料夾（DSH 官方支援的覆寫）；`USERPROFILE`、`TEMP` 也一併改到預覽資料夾。 |
| Electron 資料 | `--user-data-dir` 使用獨立 userData。單一實例鎖依 userData 判斷，所以可與正式 DSH 同時執行；本階段全程與正式 DSH 並行。 |
| SCEAN 套件 | 用 Desktop 內建的 pnpm 離線安裝，`--store-dir` 指向每個實例自己的 store。 |
| 模型 | 測試實例只註冊 scripted provider；共 148 次以上呼叫，付費 0 次。 |
| 網路 | 測試實例的 renderer 使用無效 proxy。Host 是 Electron 的 Node 模式，打包版不接受 `NODE_OPTIONS`，所以 Host 無法掛上離線攔截器。我改用連線清單檢查，沒有看到對外連線。 |

**為什麼套件版本號要不同**：第一次安裝時，pnpm 依「名稱＋版本」重用了快取，裝進的是不含 v2 的舊內容。預覽套件因此一律使用 `…stagev2-<提交>[.dev<時間>]` 版本號，也避免和正式發行版混淆。

**為什麼沒有關閉 site isolation**：上一階段在 Chrome 中關閉了它，CDP 才看得到舞台 iframe。Desktop 驗收保留 Electron 的實際設定，改讓 CDP 驅動程式用 flatten session 連進 out-of-process iframe。這樣測到的是實際的行程模型。

**正式環境檢查**：
- `E:\DSH` 沒有任何檔案變更。
- `~/.dsh` 有兩個 Card Studio 狀態檔在 02:04:21 更新。當時沒有任何預覽實例裝了 SCEAN，而之後每個預覽實例都只寫自己的資料夾，所以判斷是你正在執行的正式 DSH 寫入的。

## 4. 我主動發現並處理的問題

### 4.1 `/24` 只是表面，規則本身太寬

`core/save-bundle.mjs` 的環境路徑規則 `\/[^\s]`，會把任何「/ 加一個非空白字元」開頭的字串當成 POSIX 絕對路徑。受影響的不只單位 `/24`：

- 卡片裡以「/」開頭的任何文字；
- 玩家輸入的「/roll 1d20」；
- 角色台詞裡的「/command」。

世界日常背景工作在啟動與容量檢查時也會編碼存檔，所以這類演出的影響不限於開演。

**修正**：只把磁碟機路徑、UNC、`file://`，以及「/目錄名/…」這種至少兩段、開頭像目錄名的 POSIX 路徑視為環境路徑。卡片欄位選擇器的既有例外不變。

**取捨**：「/me/you」這類兩段且以字母開頭的文字仍會被擋。我判斷這很少見，而且漏放真實路徑的風險更高。錯誤現在附帶 JSON pointer，指出是哪個欄位。

**檢查通過、開演失敗的落差**：相容性稽核新增 `D.portability`，使用同一條規則，有真實路徑時在「檢查」階段就會失敗並指出欄位。

**回歸測試**：`tests/save-portability.test.mjs`（3 項）。TRPG fixture 的 HP 單位改回 `/24`，在 Desktop 上完成開演到遊玩的全流程。

### 4.2 一般對話裡改卡後，「作品」頁停在舊狀態

Studio 只在「創作」面板上自動讀取較新的保存版本，「作品」頁沒有。另外，只要版本不同就顯示「草稿仍保留」，即使根本沒有草稿。

**修正**：
- 沒有未保存編輯時，「作品」頁也會自動讀取。
- 提示依是否真有草稿分成兩種：沒有草稿時只說明正在讀取，並附「立即讀取」作為後備。

### 4.3 預設模式下，時間衝突沒有可行的出路

預設的「正文後結算」模式中，時間無法確定時，Host 不會在寫作前詢問。它會先寫完正文，再以 `POST_TIME_INVALID` 結算失敗，而且兩次整理機會通常已用完。v2 只告訴玩家「修改行動」。

查 Core 後確認了兩件事：
- 「繼續整理」依設計不能更換時間確認，同一個 requestId 的確認必須一致。
- 新回合帶上玩家的時間確認時，Core 會以 `playerOverride` 傳給結算。

所以正確的出路是**同一個行動、新的回合、附上時間確認**。v2 現在：
- 會說明這次卡在時間上；
- 提供「指定時間後重寫」，並先講清楚暫存正文會被取代；
- 時間面板接受這個狀態。

Host 與 Core 沒有修改。

### 4.4 測試期間順帶修正的測試工具問題

這些都是測試工具的問題，不是產品程式：
- 正文後結算的輸入欄位是 `previousClock`／`timeDefinition`，scripted provider 原本讀錯欄位，故事超過第一天後會宣稱時間倒退。
- 時段目標原本可能落在不確定範圍之前。
- 時間觸發詞原本會沿著近期對話外溢到下一回合。
- 視窗尺寸原本在 renderer 更新前就被讀取。
- Electron 不支援 CDP 的視窗大小指令，改用 Win32 `MoveWindow`。

### 4.5 調查後撤回的判斷

- **「05:30–08:29」不是時鐘錯誤**：清晨是 05:00–07:59，加上 30 分鐘後成為不確定範圍，這樣顯示是正確的。
- **舞台書架上的「這一段已保存」**：那是螢幕閱讀器專用的 live region，畫面上看不到。

### 4.6 測試意圖的更新

既有測試「optional path-like speech cannot break an otherwise portable save」原本斷言台詞「/command」會被當成路徑而丟棄。新規則下它是正常文字、會保留。

- **原本的意圖**：可選資料出現路徑時，不能讓存檔失敗。這個情況改用真實路徑測試。
- **新增**：「以 / 開頭的台詞會保留」的測試。
