# PostStat 正文後世界結算

發布版本 `1.6.3-local.w29.2d.rc3.1` 對應已驗收的 `1.6.2-local.w29.2d.rc3.1.poststat.1`，原實作基準為正式 `timecal.4`。沒有整合 Natural Runtime A/B 或自然語言 handoff 實驗。

## 權責

正常流程為 Director 規劃 → Writer 定稿 → PostStat 裁定時間與世界狀態 → Host 機械驗證及原子提交。正文明確發生的事情由 PostStat 承接；未明說的合理耗時、資源、位置、任務等由它裁量。既有過去事實與因果規則仍有效，並非每輪都要重述。未採用的創作提案不是事件，角色傳聞不是自動成立的客觀事實。

Host 不用關鍵字、正則或額外審核模型判斷正文語義。它保留身份、Run／卡片、私密存取、Blueprint、數值、時間算術、非倒退、來源版本、epoch、冪等、容量及提交／恢復守門。不能因此保證模型每次語義裁定都理想；已提交而不合意的判斷仍可由玩家回滾。

## 契約與上下文

新流程不再讓 Director 呼叫 `resolve_turn_time`，也不要求起點／終點、basis、sourceRefs、時間候選回傳或逐項舉證。Single Writer 的 Director 必填僅 `sceneIntent`；五個可選創作清單可放字串或 `{text}`，都不需要引文。Writer 只回 `finalBody`、`dialogue`；原有 Draft → Prose 路徑仍可使用。

PostStat 必填為 `time`、`stateChanges`；Memory、Player History、Event Changes 有需要才提供。時間可保持日或時段精度，不強制精確分鐘。它取得玩家原輸入、定稿正文、已提交 State／Clock、Blueprint、合法公共世界規則與既定公共計畫；不接收 Director 的完整創作規劃或 Character 私密提案。Host 自行建立來源 metadata，不讓模型重填。

Clock 區間表示目前時刻的不確定性。新時間裁定可以收窄未知範圍，不能早於已知下界，也不能覆寫玩家的結構化確認。自訂一天長度與跨午夜仍由 Host 算術處理，未知時間不會偷偷變成零點。玩家的「補充／確認時間」保留為可選覆寫。

## 公共計畫與歷史

到期不代表自動發生。PostStat 對合法公共事件 ID 回傳實際狀態；未公告計畫不提供給模型。每項結果以觀察時刻追加保存，不能把已完成的歷史事件改成未發生。`not_occurred` 是截至當輪的觀察，不是永遠不准發生；後續真正發生可追加新結果，原記錄不回寫。取消的計畫亦可隨後續敘事恢復。

跨日論壇義務與 SourceCut 仍使用確定的機械邊界。新正文及本輪新 State 不會被倒灌進較早的截點。論壇發言仍是作者的發言，日記仍屬私密，背景工作沒有被改造成全知事件裁判。

## 失敗續算

合法定稿先保存為未提交正文。PostStat 可修復的格式錯誤只續算 PostStat，保留正文，不重跑 Director／Character／Writer。每篇正文的結算派送上限為兩次，持久計數不能藉舊 checkpoint 或重新啟動補回；自動修正共用固定期限。取消、權限錯誤、來源過期、額度／容量耗盡及未知提交安全停止。

已驗證的合法結算遇到保存失敗，只恢復保存；提交回覆不明先查正式收據。公開正文讀取受人類介面權限與卡片／Run 範圍保護，只回傳正文與識別資料。續算、進度、計時及完成通知均以真正發布的 operation／attempt 為準。

介面可使用「查看已保存正文」及「繼續結算已保存正文」。兩次額度用盡或來源失效時不會無限付費重試。長延遲的模型遇到刻意格式故障時，也可能在修正前用完期限；這時保文停止，不能宣稱已提交。

## 保存與回退

新結算使用保存格式 v13、`storyState.postBodyAdjudication.v1` 能力；使用續算的 operation 與通知 sidecar 會明確升為 v2。舊格式仍可讀取，不會暗中遷移正式 Run 或改寫其時間。沒有 Clock 的舊 Run 可讀／匯出，不會偷偷補時間使其變成可續玩。

v13 資料與回滾後保留的新能力不能交給 timecal.4 舊 reader 靜默讀取。程式回退前須先保全升級後的全部玩家資料，檢查是否已有 v13／新 sidecar；不能直接覆蓋整份舊備份。玩家故事回滾與程式版本回退是不同操作。

本版經玩家驗收後獲雙倉推送與 Release 授權。完整公開來源、套件與 detached source receipt 見對應版本標籤；使用者私人素材、原始模型輸出、帳本與憑證不公開。
