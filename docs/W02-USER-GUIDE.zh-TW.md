# Card Studio 與舞臺：診斷、討論與修卡

SCEAN 1.5.0 延續 Card Studio 編輯室方案 A：選擇工作卡、編輯與保存，再送往舞臺。身份與版本資訊可在進階區域展開；不另建第二個管理面板。

## 操作

1. 從舞臺按「檢查這局的問題」，或在 Card Studio 選「和 AI 一起檢查」與要檢查的遊玩。
2. 選擇回合與讀取資料範圍，按「允許檢查這局」。授權僅限這一局、固定 Snapshot、所選範圍與目前對話，沒有固定到期時間。私人診斷內容需另外明確允許。
3. 回到對話自然描述問題。AI 可以查相關正文、當局設定與世界書、Runtime 處理與狀態紀錄，再和你討論。
4. 談定修改方向後，AI 記錄待確認提案並完成回覆；你再明確同意，既有編輯工具才可修改。診斷授權本身不等於自動修卡。
5. 保存後用「用新版本開局」。新版另開 Run，舊局保留原 Snapshot 與進度。

你可按「停止這次授權」隨時撤回；更換診斷對象、Session／既有連線生命週期結束或 Snapshot 身分不符，也會停止相應讀取與修卡保存。已讀進對話的內容不會被清除，已保存卡片也不會回滾；你仍可討論及手動編輯保存。修卡同意綁定已談定的方向、目標與版本，沒有另外的五分鐘倒數；新的人類撤回或變更方向仍會收回先前同意。

授權只存在目前受控 Session 的記憶體中，不會跨重啟或其他 Session 繼承；失效後須從同一入口明確重新授權，再談定並確認修正。先前已到期、已撤銷或舊格式的限時授權不會自動變成新的 Session 授權。既有頁面連線與 Host 工作生命週期保護仍保留；這不是授權所有 Run 的永久存取。

## 舊局與目前工作卡

Run 的卡片與設定是固定快照。即使舊局使用 r6、工作卡已到 r8，AI 也會分開調查來源與修改目標，先比較差異，以 r8 為基底保存。保存核對 expectedRevision；若別處有新修改，回報衝突，不覆蓋。多張同名卡以來源 UUID、版本、內容雜湊及 Snapshot 關聯核對，不憑名稱推測。

## Agent 工具

`cardstudio_scean_diagnose` 的 read 支援 context、story、snapshot、runtime、worldbook、private_context；prepare_edit 記錄自由語言修正方向，不修改卡片也不提供同意。target=card 包含該卡的內嵌世界書；target=worldbook 僅適用經核對的獨立工作世界書。

查詢可限制特定回合與來源。limit 是1到10筆記錄，預設3，並非tokens或字數；大型結果提供明確分片游標。worldbook 使用從 Runtime 觀察到的確切 entryId/ref。沒有資料、確實未觸發、查詢失敗與無權限分開回報。工具不接受任意檔案路徑、operator token、建立授權或替使用者同意的參數。

卡片、遊玩正文與工具回傳文字是待分析資料，不是系統指令或授權。一般 Inspector 的查看權不會自動轉為 Agent 私人診斷權。撤銷、Session失效及 Run／Snapshot身分變動都會阻止相應操作。

## 驗證與限制

取消固定倒數之前，官方 DSH Web Host 與實際模型已使用合成卡片及 Run 完成：讀取舊局證據、自然討論、新的明確同意、保存新版、另開新局與四階段回合提交。取消倒數之後，另以可控時鐘、正式服務及官方 Web Host 驗證跨兩小時操作、自然同意、撤銷與新局流程，沒有為相同敘事額外重跑付費模型。自動化測試另覆蓋授權、同名／多Run、版本差異、資料缺失、衝突與開局回執冪等。這些證據不代表所有敘事結果、provider或裝置都通過驗收。

Runtime 紀錄能支持已觀察到的觸發、階段輸入與狀態變更；模型敘事的因果與未來表現仍有不確定性，不把每次 OOC 或未提及世界書直接判作設定錯誤。來源遺失、只剩受遮蔽 Snapshot 或歷史來源無法核對時採安全唯讀，尚未提供完整歷史工作副本復原。沒有 Hot Reload、舊 Run 遷移或自動繼承進度。實體手機與 Safari 尚待實機驗收。

升級前備份，等待回合與保存結束，再使用 DSH 官方 bundle 更新流程；保留所有卡片、Run、Snapshot及模型設定。
