# 自動章節摘要與遊玩上下文

章節整合隨本次主線同步保留。單一有效摘要替代已覆蓋原文的接線已有實際回合證據；完整多章 3＋8 混合召回與新章自動分界仍未完成真實服務端到端驗收。沿用現有章節服務、模型路由、來源權限與交易；不改 Writer 文風、角色私密記憶或 post_stat 協定。

## 玩家操作

新故事預設開啟「自動整理摘要並用於後續遊玩」。既有故事缺少設定或明確關閉仍保持關閉，可在「章節與回顧」保存此單一主開關。保存、開啟頁面、匯入、重連及重啟都不會自行生成摘要或補建舊章；之後玩家正式提交回合才檢查整理時機。全域設定提供共用服務門檻及既有向量／排序來源，不再要求每次啟動後重新授權章節召回。

服務未設定、暫時失敗或章節來源失效時顯示原因；不暗換供應商。達到門檻後的分析、摘要、向量及排序可能產生既有模型服務用量。

## 資料流

1. 回合原子提交後，以未歸檔公開正文及玩家輸入估算 token。預設門檻 16,000，沿用共用 Unicode 腳本估算法；不是模型供應商精確 tokenizer，也不是整個 Prompt 的總長度上限。
2. 在完整回合邊界附近尋找章界並生成名稱與摘要。偏好保留近期六回合改為軟性偏好，保護尾段最多約門檻四分之一，避免少數超長回合使章節永久無法壓縮。
3. 模型表示尚無自然章界時，低於門檻 1.5 倍則保留原文、按冷卻規則再檢查；超過 1.5 倍可在完整回合末歸檔，保留未完成任務與因果，不把歸檔當作情節結束。保存模型原本否定結果及 Host 容量切點理由，不偽造模型同意。
4. 摘要完整涵蓋選定來源；沿用 UTF-8、實際 context budget、每批 200,000 bytes、最多 16 批限制。超長章界分析可用明示 head/tail 摘錄與完整來源 hash；摘要仍讀取全部選定原文，不把摘錄冒充完整來源。
5. Director 與 Writer 使用同一合法封包：既有 prompt／Preset、觸發世界書、當前公開 State、未被有效摘要覆蓋的原文、最近三章摘要，加上較早章節經 BM25＋向量＋既有融合／排序選出的最多八章。兩組去重，低章數不補假資料。
6. 摘要來源身份、版本、hash、可見性與活躍狀態有效才移除其覆蓋原文。查詢失敗保留合法原文並明示降級，不靜默刪除上下文。降級可能使 Prompt 較長；既有 context budget 仍生效。

舊的明確 rolling-summary API 保留相容測試；正常玩家流程不自動執行 rolling summary，也不重複注入。歷史 v1 章節保存格式仍嚴格驗證，新章節記錄 v2 容量策略。未實作失敗階段 checkpoint/resume。

## 驗證與邊界

隔離測試覆蓋新局預設、舊局關閉、重啟及全域保存、來源過期／rollback、低章數與 3＋8 去重、CJK 與超長單回合、失敗原文保留、request pin、單 Writer 及正文／State／Memory 原子提交。原生 DSH 桌面及窄窗使用 scripted 合成資料，不代表真模型品質或實體 Android 驗收。真服務結果、費用及限制另附去敏交付報告。
