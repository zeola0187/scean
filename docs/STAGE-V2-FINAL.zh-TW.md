## 決策紀錄

### D1 進階工坊重用舊版管理對話框，而不是重寫
- **問題**：v2 缺少的進階功能都在舊版舞台，而且舊版面板依賴舊版頁面骨架與共用的演出選擇狀態，逐一搬進 v2 等於重做大半個舊版。
- **考慮過**：(a) 在 v2 重寫每個設定面板；(b) 把舊版模組掛進 v2 頁面；(c) 舊版文件以「工坊模式」開啟，只顯示管理工具。
- **選擇 (c)**：v2 選單「進階工坊」以目前演出開啟舊版文件的工坊模式。故事與輸入區隱藏，主畫面是九個工具入口，每個入口觸發舊版既有按鈕、開啟已驗證的對話框：模型與服務、本局玩家／文風／面板、生成約束、記憶摘要與原文、備份匯入匯出、回收區、保存通知、診斷、來源與授權。「回到舞台」回到 v2。
- **理由**：設定、衝突處理、保存與授權邏輯 100% 沿用；工坊只是另一種呈現方式，不是第二套實作。代價是工坊外觀沿用舊版樣式，這可以接受，因為進階功能不需要沉浸感。
- **契約**：`native.stageUi` 接受 `{ui:'workshop', runId?}`；`native.bootstrap` 回傳 `stageMode`。工坊不會被記成玩家偏好的舞台。
- **驗證**：Desktop 上從 v2 選單開啟工坊、九個入口各自開啟對應對話框、回到舞台後偏好仍為新版（實際 UI 操作，scripted 實例）。

### D2 世界動態與已讀游標
- **問題**：日曆與論壇的新內容只有主動打開才看得到。
- **契約**：新增兩個 Host 動作。
  - `worldFeed {runId}`：建立在既有的公開日常讀取器之上，列出尚未看過的論壇主題、回覆，以及日常排程新公告的日曆事件（作者寫在作品裡的事件屬於劇本，不算新消息）。唯讀、不觸發任何生成、不含私密日記。
  - `worldFeedSeen {runId, forumSequence?, ids?}`：游標只會前進，存在演出旁的 `feed-cursor.json`，不屬於故事狀態，也不隨匯出。
- **已讀的定義**：玩家看到才算。也就是按「看過了」、點開某一則，或在論壇／日曆畫面上實際顯示了它。每 45 秒的背景讀取永遠不會標為已讀。
- **呈現**：寬螢幕放在右側「此刻」欄最上方；窄螢幕放在故事最後、作品面板之後（作品面板依先前驗收，緊接在最新正文後）。
- **驗證（Desktop 實際操作）**：一場演出有 3 則未讀。打開論壇列表後只剩 2 則，因為兩則回覆還沒被看到；點開該主題後歸零；重新啟動 DSH 後仍是 0。

### D3 「作品已經變更」的真正原因：舞台沒有自己的 Studio 租約
- **發現**：舞台的卡片情境來自 Card Studio 每個對話的紀錄，而這份紀錄只在有頁面持有 Studio 租約（90 秒，需續約）時存在。Studio 面板只在顯示時持有租約，所以單獨開著舞台一段時間後，情境會消失（`CARD_CONTEXT_REQUIRED`）。之後 Studio 再打開時會建立新世代，舞台就收到 `CHANGED`。另外，DSH 替換對話的 agent 物件時，紀錄也會被關閉，與租約無關。
- **修正**：
  - 原生舞台面板在開啟且可見時，透過與 Studio 面板相同的 API 持有一般頁面租約（每 20 秒續約，關閉時釋放）。
  - 每次讀取 `native.context` 前先確認租約；租約遺失時立即重新取得。
  - v2 傳輸層遇到 `CHANGED`／`REQUIRED` 時，重讀情境一次；只有同一張卡、同一個創作對話才重送。
- **我自己的錯誤**：第一版的租約程式碼找不到 Studio 的遠端服務，等於完全沒有持有租約。我當時一度以「200 秒內世代不變」判定修好了，其實那次只是 Studio 面板剛好還持有租約。之後加上診斷狀態 `window.__SCEAN_STAGE_LEASE__` 才確認問題，改為在使用時以 `remote.cardstudioScean` 查找服務。
- **驗證（Desktop）**：租約實際持有並持續續約；單獨開著舞台 210 秒，世代不變；注入一次 `REQUIRED` 後，回合仍自動恢復並提交。

### D4 「我已知的設定」：玩家自己的筆記，而不是推測的 revealedLore
- **評估過的做法**：
  - 把每回合選進寫作上下文的設定條目當成「已揭露」：不可靠，那些條目可能正是引導劇情的祕密。
  - 讓 PostStat 標記揭露了哪些條目：需要修改模型契約，本輪不動。
- **選擇**：「我已知的」分頁只放兩種東西。
  1. 作者標為公開的設定（既有的 `playerWorldbook`）。
  2. 玩家自己記下的段落：在故事裡選取文字，按跳出的「記下」。
- **契約**：新增 Host 動作 `playerNotes`／`playerNoteAdd`／`playerNoteDelete`。記下的文字必須真的出現在某個已提交段落中；段落被收回或重寫後，筆記保留但標為「已不在故事中」。存在 `player-notes.json`，不屬於故事狀態，也不會送進模型。
- **理由**：完全不推測，所以祕密不可能因為這個功能洩漏給玩家；同時玩家得到一個真正屬於自己的「已知事實」清單。

### D5 範例故事走「直接開演」，不走保存劇本
- **問題**：保存劇本前必須完成 AI 語意審閱。這是為作者作品設計的品質關卡，但新手第一次試玩就要先花一次模型呼叫，門檻太高。
- **選擇**：範例卡隨 Studio 出貨，Studio 啟動時放進 `imports`（只在缺少時寫入，不覆蓋）。按下「試玩範例故事」後，走一般匯入，再呼叫既有的 `startScean`（舊版就有的直接交接）。審閱規則沒有被繞過，因為範例根本不保存劇本。
- **一個對話一張 Seed**：如果目前對話已經有作品，會先開新的創作對話，再在那裡匯入範例。
- **連帶修正**：直接開演會留下待選的開場；v2 書架現在會偵測並開啟開場選擇。過去只有 v2 自己開演時才會處理。

### D6 視窗被遮住時的兩個問題
- **產品問題**：租約程式原本只在 `document.visibilityState === 'visible'` 時運作。DSH 視窗被遮住或最小化時，舞台會失去卡片情境，回到前景後還要等下一次檢查。改為只要舞台面板存在就持有租約，每個 Studio 請求也加上 10 秒上限。
- **測試問題**：視窗被遮住時，Chromium 不會排版 out-of-process iframe，`innerText` 讀到空白，截圖卻正常。這造成多次看似產品失敗、其實是環境問題的結果。scripted 測試實例改用 `--disable-backgrounding-occluded-windows`；個人預覽不使用這些旗標。
- **另一個測試陷阱**：作品面板本身也是 `about:srcdoc` 沙盒 iframe，原本的框架選擇器會把它誤認成舞台。改以真正的父子關係計算深度，舞台固定是第 1 層。
- **教訓**：我在這一輪有幾次把環境假象當成產品問題，也有一次把運氣當成修好。之後都先用診斷資料（`__SCEAN_STAGE_LEASE__`、Host 端 `debug-context.jsonl`）確認，再下結論。
